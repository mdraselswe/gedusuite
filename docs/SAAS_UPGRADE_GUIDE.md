# GeduSuite → SaaS Upgrade Guide

> ব্রাঞ্চ: `saas-upgrade` (শুরু হয়েছে `main` @ `ae6e299` থেকে)
> লক্ষ্য: GeduShop-এর চলমান প্রোডাকশন কিছু না ভেঙে GeduSuite-কে মাসিক/বাৎসরিক
> সাবস্ক্রিপশনে বিক্রয়যোগ্য প্রোডাক্টে রূপান্তর।
> বাংলা UI এই গাইডের আওতার বাইরে (আপাতত নয়)।

---

## ০. কাজের নিয়ম (সব ফেজে প্রযোজ্য)

### ০.১ প্রোডাকশন সুরক্ষা
| নিয়ম | কারণ |
|---|---|
| সব কাজ `saas-upgrade` ব্রাঞ্চে। `main`/`production`-এ কোনো কমিট নয় | প্রোডাকশন Vercel `production` ব্রাঞ্চ থেকে ডেপ্লয় হয় |
| ব্রাঞ্চ `origin`-এ **পুশ করা হবে না** যতক্ষণ না আপনি বলেন | Vercel preview build-এ `DATABASE_URL` থাকলে `prisma migrate deploy` প্রোডাকশন DB-তে চলতে পারে |
| `.env.local` **আসল প্রোডাকশন Neon DB**-র দিকে নির্দেশ করে — এটি দিয়ে কোনো টেস্ট/সিড/মাইগ্রেশন চলবে না | লোকাল `yarn dev` চালালে প্রোডাকশন ডেটা বদলে যায় |
| লোকাল কাজ হবে আলাদা `.env.saas.local` + **লোকাল Postgres** | সম্পূর্ণ বিচ্ছিন্ন |
| মাইগ্রেশন শুধু **additive**: নতুন টেবিল, নতুন nullable/default-সহ কলাম। কোনো কলাম মোছা/রিনেম/টাইপ বদল নয় | পুরোনো কোড-ও নতুন schema-য় চলবে, রোলব্যাক নিরাপদ |
| হিসাবের ফাইল (`finance.ts`, `orders.ts`, `order-cash.ts`, `courier.ts`, `reports.ts`, `inventory.ts`, `profit-share.ts`, `treasury-pot.ts`, `amortize.ts`, `money.ts`, `funding.ts`) **পরিবর্তন নিষিদ্ধ** | "হিসাবে ভুল থাকা যাবে না" |
| বিদ্যমান ওয়েবহুক URL, secret, env-var নাম অপরিবর্তিত থাকবে | Woo/Steadfast/cron ভাঙা যাবে না |

### ০.২ রিগ্রেশন-গার্ড: Golden Master
ফেজ ০-তে `main`-এর কোড দিয়ে একটা নির্ধারিত (deterministic) ডেমো ডেটাসেটের উপর
সব রিপোর্ট/ড্যাশবোর্ড/ট্রেজারি/পার্টনার ফিগার গণনা করে একটি JSON "golden"
ফাইলে সংরক্ষণ করা হবে। **প্রতিটি ফেজের পর** একই গণনা চালিয়ে
গোল্ডেনের সাথে হুবহু মেলানো হবে। এক টাকাও অমিল হলে ফেজ অসম্পূর্ণ।

### ০.৩ প্রতিটি ফেজের "Done" শর্ত
1. `yarn typecheck` — এরর শূন্য
2. `yarn test` — সব পাস (বিদ্যমান ৫৯৩ + নতুন)
3. `yarn lint`-ফ্রি নতুন ফাইল (যেখানে প্রযোজ্য)
4. Golden Master অপরিবর্তিত
5. লোকাল DB-তে পরিষ্কার schema থেকে `prisma migrate deploy` সফল **এবং**
   বিদ্যমান-ডেটা-সহ DB-তে (ফেজ শুরুর snapshot) সফল
6. ফেজের নিজস্ব ইন্টিগ্রেশন/E2E টেস্ট পাস
7. `docs/SAAS_UPGRADE_LOG.md`-তে ফেজ রিপোর্ট (কী বদলাল, কী টেস্ট হলো, কী অযাচাইকৃত)

### ০.৪ কমিট ও ডেপ্লয়
- প্রতি ফেজে আলাদা কমিট-সিরিজ (`feat(phase-N): ...`)।
- কোনো ডেপ্লয় নয়। সব ফেজ শেষে একসাথে আপনি লোকালি দেখবেন → তারপর ডেপ্লয়।
- ডেপ্লয়ের দিন: Neon snapshot → মাইগ্রেশন অগ্রিম প্রোডাকশন-কপি ব্রাঞ্চে → `production`-এ মার্জ।

## ফেজ ০ — নিরাপত্তা-জাল ও লোকাল পরিবেশ

**লক্ষ্য:** প্রোডাকশন না ছুঁয়ে নিরাপদে কাজ করা ও পরীক্ষা করার ভিত্তি।

| কাজ | বিস্তারিত |
|---|---|
| ০.১ লোকাল DB | `embedded-postgres` (devDependency) দিয়ে `yarn db:local:start`; কোনো Docker/অ্যাকাউন্ট লাগবে না |
| ০.২ Prisma ক্লায়েন্ট | `src/lib/prisma.ts`: DATABASE_URL-এর হোস্ট `neon.tech` হলে **আগের মতোই** PrismaNeon; অন্যথায় `@prisma/adapter-pg`। প্রোডাকশন আচরণ অপরিবর্তিত |
| ০.৩ env গার্ড | `.env.saas.local` লোড; `scripts/assert-safe-db.mjs` — DB হোস্টে `ep-wispy-pine` (প্রোডাকশন) থাকলে সব সিড/টেস্ট স্ক্রিপ্ট অস্বীকার করবে |
| ০.৪ CI | `.github/workflows/ci.yml`: typecheck + test (পরে আপনি GitHub-এ পুশ করলে কাজ করবে) |
| ০.৫ Golden Master | `scripts/golden/` — ডেটা সিড + গণনা + তুলনা; **`main`-এর কোডে** প্রথম গোল্ডেন তৈরি |
| ০.৬ গোল্ডেন-ফ্লো চেকলিস্ট | `docs/GOLDEN_FLOWS.md` — হাতে/E2E-তে যাচাইয়ের মূল ফ্লো |

**ঝুঁকি:** `prisma.ts` পরিবর্তন — প্রোডাকশন হোস্টে শাখা-পথ অপরিবর্তিত থাকে, হোস্ট-চেক টেস্টেড।

## ফেজ ১ — নিরাপত্তা ও অ্যাকাউন্ট লাইফসাইকেল

| কাজ | বিস্তারিত | পুরোনো ইউজারের উপর প্রভাব |
|---|---|---|
| ১.১ Mailer | `src/lib/mailer.ts`; Resend HTTP API (`RESEND_API_KEY`, `MAIL_FROM`); ডেভ-এ কনসোল/ফাইল আউটবক্স। প্রোভাইডার-নিরপেক্ষ ইন্টারফেস | কোনো প্রভাব নেই |
| ১.২ ইমেইল ভেরিফিকেশন | টোকেন টেবিল (NextAuth-র `VerificationToken` পুনঃব্যবহার); নতুন সাইনআপে ইমেইল; **বিদ্যমান ইউজাররা "ভেরিফায়েড" ধরা হবে** (backfill মাইগ্রেশন) | লগইন ব্লক নয় |
| ১.৩ পাসওয়ার্ড রিসেট | `/forgot-password`, `/reset-password/[token]`, এক-ব্যবহারযোগ্য, ৩০ মিনিট মেয়াদ, ইমেইল enumeration-নিরাপদ | নতুন ফিচার |
| ১.৪ রেট-লিমিট | `RateLimit` টেবিল (সার্ভারলেস-বান্ধব, Redis ছাড়া); লগইন, রেজিস্টার, রিসেট, ইনভাইট-অ্যাকসেপ্ট। উদার থ্রেশহোল্ড, ইমেইল+IP কী | উদার, ভুল-লক এড়ানো |
| ১.৫ লিংকিং ফিক্স | `allowDangerousEmailAccountLinking` সরিয়ে signIn callback-এ নিরাপদ লিংক: শুধু Google-ভেরিফায়েড ইমেইল **এবং** বিদ্যমান ইউজারের ইমেইল ভেরিফায়েড হলে | বিদ্যমান Google/পাসওয়ার্ড ইউজার লগইন করতে পারবে (টেস্টে কভার) |
| ১.৬ সিকিউরিটি হেডার | HSTS, X-Content-Type-Options, Referrer-Policy, frame-ancestors; CSP প্রথমে **Report-Only** | ভাঙার ঝুঁকি কম |
| ১.৭ এরর রিপোর্টিং | `reportError()` হুক; `SENTRY_DSN` থাকলে Sentry (ঐচ্ছিক) | কোনো প্রভাব নেই |
| ১.৮ মেম্বারশিপ সতেজতা | proxy-র JWT-ক্যাশ: সরানো মেম্বার/রোল পরিবর্তন সর্বোচ্চ N মিনিটে কার্যকর (jwt callback-এ পুনঃলোড) | কোনো প্রভাব নেই |
| ১.৯ এনক্রিপশন কী | `BACKUP_ENCRYPTION_KEY` ফলব্যাক `NEXTAUTH_SECRET`-এ থাকলে সতর্কতা লগ; কী-ভার্সন প্রিফিক্স (পুরোনো ডেটা পড়া যাবে) | পুরোনো ciphertext পড়া অক্ষুণ্ণ |

## ফেজ ২ — মাল্টি-টেন্যান্ট ইন্টিগ্রেশন ও ব্যাকআপ

| কাজ | বিস্তারিত |
|---|---|
| ২.১ `WorkspaceIntegration` টেবিল | প্রতি workspace: Woo URL, consumer key/secret, write key/secret, webhook secret, cart-beacon secret (সব এনক্রিপ্টেড) |
| ২.২ রিজলভার | `resolveWooConfig(workspace)`: DB সেটিংস থাকলে সেটা; **না থাকলে** `WOO_WORKSPACE_SLUG` মিললে env-var ফলব্যাক। GeduShop কোনো কনফিগ না বদলেই চলবে |
| ২.৩ ওয়েবহুক | বিদ্যমান `/api/cron/woo-lead` অপরিবর্তিত পথ। নতুন `/api/hooks/woo/[workspaceToken]` অন্য টেন্যান্টদের জন্য |
| ২.৪ সেটিংস UI | Settings → Integrations: Woo সংযোগ, ওয়েবহুক URL/secret দেখানো, টেস্ট-কানেকশন |
| ২.৫ হার্ডকোড অপসারণ | `wp.gedushop.com`, `app.gedushop.com` ফলব্যাক, গিফট ট্যাগ/লিফলেট/অর্ডার-ফর্মের GeduShop টেক্সট → workspace সেটিংস (ডিফল্ট মান = বর্তমান GeduShop মান, তাই আউটপুট একই) |
| ২.৬ অফ-সাইট ব্যাকআপ | S3-সামঞ্জস্যপূর্ণ (Cloudflare R2/S3) আপলোড; `BACKUP_S3_*` env থাকলে সক্রিয়। DB-payload ব্যাকআপ চলতেই থাকবে |
| ২.৭ ব্যাকআপ ক্রন | সিকোয়েনশিয়াল লুপ → সীমিত ব্যাচ + `lastJsonAt` অনুযায়ী বাছাই, টাইমবাজেট শেষে পরের রানে |
| ২.৮ ডেটা এক্সপোর্ট | ইউজার-সুবিধার্থে "আমার সব ডেটা ডাউনলোড" |
| ২.৯ অ্যাকাউন্ট ডিলিশন | ইউজার অ্যাকাউন্ট মোছা (একমাত্র OWNER হলে আগে workspace হস্তান্তর/মোছা বাধ্যতামূলক) |

**সর্বোচ্চ ঝুঁকি এখানে** (লিড আসা বন্ধ হওয়া)। প্রতিরোধ: env পথ অক্ষত + বিদ্যমান
URL অপরিবর্তিত + ওয়েবহুক কন্ট্রাক্ট টেস্ট (HMAC, ping, malformed body)।

## ফেজ ৭ — ডেমো, টেস্ট ও ভিডিও

### ৭.১ ডেমো workspace ও টেস্ট ইউজার
- সিড স্ক্রিপ্ট `scripts/demo/seed.mjs` (ইডেমপোটেন্ট, শুধু সেফ-DB-তে)
- ইউজার: `demo@gedusuite.test` (পাসওয়ার্ড স্ক্রিপ্ট-আউটপুটে; কমিটে সংরক্ষিত নয়),
  রোল OWNER; অতিরিক্ত ডেমো MANAGER/STAFF
- ডেটা: ~৩ মাসের বাস্তবসম্মত ব্যবসা — প্রোডাক্ট/ভ্যারিয়েন্ট/কম্বো, সরবরাহকারী,
  ক্রয়, অর্ডার (সব স্ট্যাটাস, COD/রিটার্ন/আংশিক ডেলিভারি), কুরিয়ার পেআউট,
  পার্টনার (বিনিয়োগ/উত্তোলন/ডিস্ট্রিবিউশন), ট্রেজারি, ইন্টারনাল পারচেজ,
  বুস্টিং ক্যাম্পেইন, লিড/কল লিস্ট, নোটিফিকেশন
- **হিসাব বিশ্বাসযোগ্য করার উপায়:** ডেটা সরাসরি SQL-এ ছড়িয়ে নয় — অ্যাপের
  নিজস্ব সার্ভার-অ্যাকশন/ডোমেইন ফাংশন দিয়ে তৈরি, যাতে স্টক, ট্রেজারি,
  কুরিয়ার-ফি, প্রফিট একই সূত্রে মেলে। তারপর **ইন্টিগ্রিটি চেক**: স্টক =
  ক্রয় − বিক্রয় ± সমন্বয়, ট্রেজারি ব্যালেন্স = এন্ট্রির যোগফল,
  পার্টনার ব্যালেন্স ইত্যাদি অ্যাসার্ট

### ৭.২ স্বয়ংক্রিয় যাচাই
- ডেমো ইউজার দিয়ে Playwright E2E: প্রতিটি মডিউল ও গোল্ডেন-ফ্লো, কনসোল-এরর/৫xx শূন্য
- সব পেজের স্ক্রিনশট
- **ভূমিকা-ভিত্তিক** চেক: OWNER/PARTNER/MANAGER/STAFF যা দেখতে পায়/পায় না
- **টেন্যান্ট-আইসোলেশন** টেস্ট: workspace A-র ইউজার B-র ডেটা অ্যাকশন/URL দিয়ে ছুঁতে পারে না

### ৭.৩ প্রোডাক্ট প্রিভিউ ভিডিও
- Playwright `recordVideo` দিয়ে ডেমো workspace-এ স্ক্রিপ্টেড ওয়াকথ্রু (`.webm` → `.mp4`)
- দৃশ্যক্রম: ল্যান্ডিং → লগইন → ড্যাশবোর্ড → অর্ডার তৈরি → কুরিয়ার বুকিং →
  ডেলিভারি → ক্যাশ ট্রেজারিতে → পার্টনার প্রফিট → রিপোর্ট → বুস্টিং ROI → মোবাইল
- আউটপুট: `demo-assets/` ( আপনার আলাদা এডিটিং/ভয়েসওভার অপশনাল)
