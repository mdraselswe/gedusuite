# চালানো, ডেমো দেখানো, আর ডেপ্লয় — গাইড

এই ব্রাঞ্চ (`saas-upgrade`) এখনও কোথাও ডেপ্লয় হয়নি, কোথাও পুশও হয়নি।
`main` ও `production` ব্রাঞ্চ অপরিবর্তিত।

## ১. লোকালি চালানো (প্রোডাকশন ডেটাবেসে হাত না দিয়ে)

> `.env.local`-এ আপনার **আসল প্রোডাকশন** ডেটাবেস আছে। এই ব্রাঞ্চের সব
> কমান্ড `.env.saas.local` ব্যবহার করে, যা শুধু লোকাল Postgres-এ যায়।

তিনটি টার্মিনালে, প্রজেক্ট ফোল্ডার থেকে:

```bash
yarn db:local          # ১. লোকাল ডেটাবেস (চালু রাখুন)
yarn local:migrate     # ২. একবার — টেবিল তৈরি
yarn demo:seed         # ৩. ডেমো ডেটা (~১.৫ মিনিট)
yarn local:dev         # ৪. অ্যাপ  → http://localhost:3000
```

প্রোডাকশন-মোডে দ্রুত দেখতে:
`npx dotenv -e .env.saas.local -- npx next build --webpack` তারপর `yarn local:start`।

## ২. ডেমো ইউজার (যেকোনো কাস্টমারকে দেখানোর জন্য)

| | |

| মালিক | `demo@gedusuite.test` / `Demo#2026` |

ডেটা: ৯০ দিনের একটি শিশু-পণ্যের দোকান — ~২৫০ অর্ডার, ক্রয়, কুরিয়ার, ট্রেজারি,
পার্টনার (৫০/৩০/২০%), বিজ্ঞাপন (২টি ক্যাম্পেইন), ওয়েবসাইট লিড, আংশিক পেমেন্ট,
ফেরত আসা পার্সেল, মেয়াদোত্তীর্ণ হতে চলা পণ্য, কম স্টক।

**হিসাব বিশ্বাসযোগ্য কেন:** ডেটা হাতে লেখা নয় — অ্যাপের নিজস্ব অ্যাকশন দিয়ে
তৈরি, তাই স্টক, ট্রেজারি, কুরিয়ার ফি, প্রফিট একে অপরের সাথে মেলে। আর
`tests/integration/integrity.itest.ts` ডেটা তৈরির পর স্বাধীনভাবে যাচাই করে: ট্রেজারি =
ইন − আউট, কোনো স্টক নেগেটিভ নয়, প্রতিটি ব্যাংক করা অর্ডারের এন্ট্রি = কুরিয়ার
যা পাঠিয়েছে, প্রফিট ডিস্ট্রিবিউশনে এক টাকাও হারায় না।

> ⚠️ ইন্টিগ্রেশন টেস্ট চালালে লোকাল ডেটাবেস মুছে যায়। টেস্টের **পরে**
> `yarn demo:seed` আবার চালান।

## ৪. টেস্ট চালানো

```bash
yarn test                 # ৬২১টি ইউনিট টেস্ট (ডেটাবেস লাগে না)
yarn test:integration     # ৫৯টি — আসল অ্যাকশন + Golden Master + রোল/টেন্যান্ট
yarn typecheck            # অ্যাপ + টেস্ট দুটোই
```

**Golden Master** (`tests/golden/baseline.json`): `main`-এর কোডে তৈরি একটি
নির্দিষ্ট ব্যবসার সব আর্থিক ফিগার। প্রতিটি ফেজের পর হুবহু মিলেছে — অর্থাৎ
হিসাবে কিছু বদলায়নি।

## ৫. ডেপ্লয়ের আগে (ক্রমানুসারে)

1. **Neon snapshot/branch** নিন (আপনার প্রোডাকশন DB-র)।
2. সেই branch-এর কপিতে মাইগ্রেশন চালিয়ে দেখুন:
   `DATABASE_URL=<copy> DIRECT_URL=<copy> npx prisma migrate deploy`
   (৩টি নতুন মাইগ্রেশন, সবই additive: `account_security`,
   `workspace_integration`, `plans_and_billing`)।
3. **`npx next build --webpack` ফোরগ্রাউন্ডে চালান** — টাইপচেক ও টেস্ট ধরতে পারে না
   এমন সমস্যা (যেমন `"use server"` ফাইলে non-async export) এটা ধরে।
4. Vercel-এ এনভায়রনমেন্ট ভ্যারিয়েবল (নিচের টেবিল)।
5. **প্রথম ডেপ্লয়ে `BILLING_ENFORCEMENT` সেট করবেন না** (বন্ধ থাকলে কারো কিছু আটকায় না)।
6. `production` ব্রাঞ্চে মার্জ → ডেপ্লয় → [গোল্ডেন ফ্লো](GOLDEN_FLOWS.md) হাতে চালিয়ে দেখুন।
7. কয়েকদিন পর ঠিক মনে হলে `BILLING_ENFORCEMENT=on`।

### এনভায়রনমেন্ট ভ্যারিয়েবল (নতুন)

| নাম | কী জন্য | না দিলে |
|---|---|---|
| `RESEND_API_KEY`, `MAIL_FROM` | ইমেইল (ভেরিফাই, পাসওয়ার্ড রিসেট, রিমাইন্ডার) | ইমেইল যায় না (লগে সতর্কতা); নতুন ইউজার ভেরিফাই করতে পারবে না |
| `PLATFORM_ADMIN_EMAILS` | আপনার ইমেইল — `/admin` খুলবে | অ্যাডমিন প্যানেল কেউ খুলতে পারবে না |
| `BILLING_BKASH_NUMBER`, `BILLING_NAGAD_NUMBER`, `BILLING_BANK_DETAILS` | কাস্টমার কোথায় টাকা পাঠাবে | পেমেন্ট পেজে "যোগাযোগ করুন" দেখায় |
| `BILLING_SUPPORT_EMAIL`, `BILLING_SUPPORT_PHONE` | সাপোর্ট যোগাযোগ, ফুটার, সাপোর্ট ফর্ম | সাপোর্ট ফর্ম কাজ করবে না |
| `BILLING_ENFORCEMENT=on` | প্ল্যান লিমিট/রিড-অনলি চালু | বন্ধ (ডিফল্ট, নিরাপদ) |
| `BACKUP_S3_ENDPOINT`, `_BUCKET`, `_ACCESS_KEY`, `_SECRET_KEY` | অফ-সাইট এনক্রিপ্টেড ব্যাকআপ | ব্যাকআপ শুধু ডেটাবেসে |
| `SENTRY_DSN` | এরর রিপোর্টিং | শুধু লগ |
| `APP_URL` (ঐচ্ছিক) | ইমেইলের লিংকের ঠিকানা | `NEXTAUTH_URL` |

বিদ্যমান ভ্যারিয়েবল (`WOO_*`, `WC_*`, `WP_URL`, `CRON_SECRET`, …) যেমন আছে তেমনই থাকবে।

### আপনার GeduShop ওয়ার্কস্পেসের কী হবে

- প্ল্যান: স্বয়ংক্রিয়ভাবে **LEGACY** — আনলিমিটেড, কখনো মেয়াদ শেষ হয় না।
