# একটি স্বাধীন (independent) GeduSuite প্রোডাকশন চালু করা

লক্ষ্য: GeduShop-এর বর্তমান প্রোডাকশন থেকে **সম্পূর্ণ আলাদা** একটি ইনস্টলেশন, যেখান
থেকে আপনি সাবস্ক্রিপশন বিক্রি করবেন। আলাদা ডেটাবেস, আলাদা Vercel প্রজেক্ট, আলাদা
ডোমেইন, আলাদা সিক্রেট। GeduShop-এর কোনো ডেটা, কী বা ডোমেইন এতে নেই।

> পুরোনো GeduShop প্রোডাকশন এখনকার মতোই চলবে। সময় হলে সেটিকেও এই নতুন
> প্ল্যাটফর্মের একজন কাস্টমার হিসেবে যোগ করা যাবে (§৮)।

## ১. যা লাগবে (একবারের সেটআপ)

| কী | কেন | খরচ |
|---|---|---|
| **নতুন Neon প্রজেক্ট** | আলাদা ডেটাবেস | ফ্রি টিয়ার দিয়ে শুরু, বিক্রি শুরু হলে পেইড |
| **নতুন Vercel প্রজেক্ট** (Pro) | অ্যাপ হোস্টিং (বাণিজ্যিক ব্যবহারে Pro লাগে) | ~$20/মাস |
| **ডোমেইন** (যেমন `gedusuite.com`) | অ্যাপের ঠিকানা | ~$12/বছর |
| **Resend অ্যাকাউন্ট** + ডোমেইন ভেরিফাই | ইমেইল (ভেরিফাই, রিসেট, রিমাইন্ডার) | ফ্রি টিয়ার |
| **Google Cloud OAuth ক্লায়েন্ট** (নতুন) | "Sign in with Google" ও Drive ব্যাকআপ | ফ্রি |
| bKash/Nagad মার্চেন্ট/পার্সোনাল নম্বর | গ্রাহকের পেমেন্ট গ্রহণ | — |
| (ঐচ্ছিক) Cloudflare R2 বাকেট | অফ-সাইট এনক্রিপ্টেড ব্যাকআপ | ~ফ্রি |
| (ঐচ্ছিক) Sentry | এরর রিপোর্টিং | ফ্রি টিয়ার |

> **GeduShop-এর Neon/Vercel/Google প্রজেক্ট আবার ব্যবহার করবেন না।**

## ২. ধাপে ধাপে

1. **Neon:** নতুন প্রজেক্ট → `DATABASE_URL` (pooled) ও `DIRECT_URL` (unpooled) কপি।
2. **Vercel:** এই রিপোজিটরির `production` ব্রাঞ্চ (বা আপনার নতুন রিপো) থেকে **নতুন প্রজেক্ট**।
   Framework: Next.js। Build command: `yarn vercel-build` (আগে থেকেই সেট থাকে — `vercel.json`/
   `package.json`)। প্রথম ডেপ্লয়ে মাইগ্রেশন নিজে থেকে চলবে (`prisma migrate deploy`)।
3. **ডোমেইন:** Vercel → Settings → Domains → যোগ করুন, DNS রেকর্ড বসান।
4. **Google OAuth:** Google Cloud → নতুন প্রজেক্ট → OAuth ক্লায়েন্ট (Web)। Authorized redirect URI:
   - `https://<আপনার-ডোমেইন>/api/auth/callback/google`
   - `https://<আপনার-ডোমেইন>/api/google/personal/callback`
5. **Environment variables** (Vercel → Settings → Environment Variables, **Production**):

| নাম | মান |
|---|---|
| `DATABASE_URL`, `DIRECT_URL` | Neon থেকে |
| `NEXTAUTH_URL` | `https://<আপনার-ডোমেইন>` |
| `NEXTAUTH_SECRET` | `openssl rand -base64 32` |
| `BACKUP_ENCRYPTION_KEY` | আলাদা একটি র‍্যান্ডম মান — **একবার সেট করে আর বদলাবেন না** (বদলালে সংরক্ষিত কী/টোকেন পড়া যাবে না) |
| `CRON_SECRET` | র‍্যান্ডম |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | ধাপ ৪ থেকে |
| `RESEND_API_KEY`, `MAIL_FROM` | যেমন `GeduSuite <no-reply@আপনার-ডোমেইন>` |
| `PLATFORM_ADMIN_EMAILS` | আপনার ইমেইল (কমা দিয়ে একাধিক) |
| `BILLING_BKASH_NUMBER`, `BILLING_NAGAD_NUMBER`, `BILLING_BANK_DETAILS` | পেমেন্ট গ্রহণের ঠিকানা |
| `BILLING_SUPPORT_EMAIL`, `BILLING_SUPPORT_PHONE` | সাপোর্ট |
| `BILLING_ENFORCEMENT` | **প্রথমে সেট করবেন না**; ট্রায়ালে নিজে পরীক্ষা করে `on` |
| `BACKUP_S3_ENDPOINT`, `_BUCKET`, `_ACCESS_KEY`, `_SECRET_KEY` | (ঐচ্ছিক) অফ-সাইট ব্যাকআপ |
| `SENTRY_DSN` | (ঐচ্ছিক) |

**সেট করবেন না:** `WP_URL`, `WC_*`, `WOO_*`, `CART_BEACON_SECRET` — এগুলো পুরোনো একক-দোকান
মোডের। নতুন ইনস্টলেশনে প্রতিটি কাস্টমার নিজের ওয়ার্কস্পেসে (Settings → Website) নিজের
WooCommerce যুক্ত করে।

6. **প্রথম অ্যাডমিন:** অ্যাপে `PLATFORM_ADMIN_EMAILS`-এর ইমেইল দিয়ে সাইন-আপ → ইমেইল ভেরিফাই
   → `/admin` খুলবে।
7. **স্মোক টেস্ট** (আপনি নিজে, ১০ মিনিট): নতুন অ্যাকাউন্ট → workspace → পণ্য → ক্রয় →
   অর্ডার → ডেলিভারি → ট্রেজারি → রিপোর্ট; পাসওয়ার্ড রিসেট; একটি প্ল্যান কিনে `/admin/payments`
   থেকে অনুমোদন। (`docs/GOLDEN_FLOWS.md`)
8. তারপর `BILLING_ENFORCEMENT=on`।

## ৩. কী "স্বাধীন" — কাস্টমার নিজে নিজের জন্য সেট করে

| বিষয় | কোথায় |
|---|---|
| দোকানের নাম, লোগো, ওয়েবসাইট | Settings → Appearance |
| গিফট ট্যাগ / লিফলেটের লেখা, ফেসবুক, WhatsApp | Settings → Appearance → Printed extras |
| ইনভয়েস ও অর্ডার-ফর্ম | ওয়ার্কস্পেসের নাম/লোগো/ওয়েবসাইট স্বয়ংক্রিয়ভাবে |
| কুরিয়ার, জোন, রেট, API কী | Couriers |
| ওয়েবসাইট (WooCommerce) | Settings → Website (প্ল্যান Pro) |
| কম্বো প্লাগিন | Settings → Website থেকে ডাউনলোড (`/downloads/gedusuite-combo.zip`) |
| টিম ও রোল | Settings → Team |
| পণ্যের ক্যাটাগরি | Products (ডিফল্ট সাধারণ ক্যাটাগরি, সম্পাদনযোগ্য) |

## ৪. ব্যাকআপ ও পুনরুদ্ধার (আপনার নিজের দায়িত্ব — গ্রাহকদের ডেটা)

- Neon: Point-in-time restore চালু রাখুন; বড় পরিবর্তনের আগে branch/snapshot নিন।
- অ্যাপের দৈনিক JSON ব্যাকআপ ডেটাবেসের ভেতরেই থাকে; **অফ-সাইট (R2/S3) চালু করুন**।
- ত্রৈমাসিকে একবার একটি ব্যাকআপ আসলেই পুনরুদ্ধার করে দেখুন।

## ৫. আপডেট দেওয়ার নিয়ম

1. লোকালে `yarn test`, `yarn test:integration`, `npx next build --webpack`।
2. Neon branch-এর কপিতে নতুন মাইগ্রেশন চালিয়ে দেখুন।
3. তারপর মার্জ → Vercel ডেপ্লয়।
4. মাইগ্রেশন সবসময় additive (কলাম মোছা/রিনেম নয়)।

## ৬. আইনি / ব্যবসায়িক (কোডে সমাধান হয় না)

- Terms, Privacy, Refund-এর খসড়া আইনজীবীকে দিয়ে দেখান।
- ব্যবসা/ট্রেড লাইসেন্স, ট্যাক্স, ভ্যাট প্রযোজ্য কিনা জানুন।
- বাংলাদেশ ডেটা-সুরক্ষা আইন ও গ্রাহকের ফোন/ঠিকানা সংরক্ষণ সংক্রান্ত দায়বদ্ধতা।
- কাস্টমার সাপোর্টের প্রতিশ্রুত সময়সীমা (SLA) ঠিক করুন।

## ৭. পরিচালনা (দৈনিক/সাপ্তাহিক)

- `/admin/payments` — জমা পড়া পেমেন্ট যাচাই (প্রতিদিন)।
- `/admin` — ট্রায়াল/মেয়াদ, সাসপেন্ড, ব্যবহার।
- Vercel লগ/Sentry — এরর; Neon — ডেটাবেস ব্যবহার।
- কুরিয়ার/Woo সংযোগ নিয়ে সাপোর্ট অনুরোধ আসে `BILLING_SUPPORT_EMAIL`-এ।

## ৮. GeduShop-কে পরে এই প্ল্যাটফর্মে আনা (ঐচ্ছিক)

আলাদা সিদ্ধান্ত, ডেটা মাইগ্রেশন লাগে: পুরোনো ডেটাবেসের একটি ওয়ার্কস্পেস JSON ব্যাকআপ
(`Settings → Backup`) → নতুন ইনস্টলেশনে ওয়ার্কস্পেস তৈরি → Restore। এটি কোনোভাবেই
এখন করার দরকার নেই; এবং করার আগে পুরোনো প্রোডাকশন চালু রেখেই নতুনটিতে পুরো
মিলিয়ে দেখতে হবে।
